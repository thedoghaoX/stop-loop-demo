# Stop-Loop Demo：你的 AI 為什麼一直轉圈圈？因為它沒有人叫它停。

很多人用 AI 寫程式或跑任務時都遇過同一件事：  
去倒杯水回來，發現它在同一個小錯裡面自己重試了幾十次，把你一整個禮拜的額度跟時間默默燒光。

**真正讓人放心的 AI，不是永遠不會寫錯，而是「它知道什麼時候該停」。**

這個儲存庫用每個人都看懂的簡單小函式（**階乘 `factorial(n)`** 與 **字串反轉 `reverse_text(s)`**），故意埋一個邊界條件的錯，讓你在 10 秒鐘內親眼看到兩個瞬間：
1. **修好就停**：第 1 步抓到 `factorial(0)` 邊界錯誤 ➔ 第 2 步修好通過 ➔ **立刻自己收手停機**，絕不多跑半步廢話。
2. **卡住也停**：遇到死胡同連續 2 步沒有推進 ➔ **立刻自己拉下煞車回報**，把你剩下的額度全留在真正有推進的地方。

## 一鍵體驗（零額外套件，複製貼上就能跑）

### 方式 A：單行指令直接看它「自己停下來」（10 秒）
```bash
git clone https://github.com/thedoghaoX/stop-loop-demo.git && cd stop-loop-demo && python3 stop_loop_demo.py
```

### 方式 B：不下載檔案，一行 Python 直接跑
```bash
python3 -c 'import urllib.request; exec(urllib.request.urlopen("https://raw.githubusercontent.com/thedoghaoX/stop-loop-demo/main/stop_loop_demo.py").read().decode("utf-8"))'
```

## 終端機實際輸出

```text
====================================================================
【示範 1】寫一個階乘函式 factorial(n)（故意埋 n=0 的邊界條件錯誤）
====================================================================

▶ 第 1 步（初稿）
  程式碼：if n > 1: return n * f(n-1) else: return n
  測試結果：2/3 通過（本步推進：+2）
  ❌ 抓到問題：邊界條件 factorial(0) == 1 -> 預期 1，實測拿到 0

▶ 第 2 步（修正邊界）
  程式碼：if n <= 1: return 1 else: return n * f(n-1)
  測試結果：3/3 通過（本步推進：+1）

🛑 [它自己停了！] 外部檢查確認 3/3 測試全數通過。
   總共只跑 2 步就自動收手，不繼續多燒半步額度。

====================================================================
【示範 2】字串反轉 reverse_text(s) 遇到死胡同時，幾步內自動收手？
====================================================================
  情境：如果測試環境卡住、或修改方向連續 2 步都沒讓通過數增加：
  ▶ 第 1 步（嘗試修改 A）：卡在空白字元邊界條件（通過 2/3）
  ▶ 第 2 步（嘗試修改 B）：依然卡在同一題（通過 2/3，推進 +0）
  ▶ 第 3 步（嘗試修改 C）：依然卡在同一題（通過 2/3，推進 +0）

🛑 [它自己停了！] 偵測到連續 2 步沒有實質推進，自動收手並回報卡關原因。
   不會像沒人管的 AI 一樣原地轉圈圈跑完 200 步把你的額度燒光。
```

## 螢幕錄影規格說明（9 秒短影音 ＆ 2 分鐘完整實測版）

### 1. 社群 9 秒短影音版（一眼看懂「它自己停了」）
- **0.0s – 2.5s**：畫面顯示一般沒有煞車的 AI 在邊界錯誤裡無限重試（計步器狂跳、額度條快速流失）。
- **2.5s – 6.0s**：執行 `python3 stop_loop_demo.py`，第 1 步抓到 `factorial(0)` 預期 `1` 卻拿到 `0`，第 2 步修正 `n <= 1` 通過。
- **6.0s – 9.0s**：終端機跳出 **`🛑 [它自己停了！]`**，畫面定格高亮：「只花 2 步自動收手，額度全花在真的推進的地方」。

### 2. 兩分鐘完整螢幕錄影規格（從啟動到它自己喊停）
- **00:00 – 00:25（問題重現）**：打開終端機，展示一個日常小任務（寫 `factorial(n)` 或 `reverse_text(s)`），故意把 `n = 0` 的邊界條件寫錯。說明一般 AI 沒人幫它盯測試、沒人叫它停時，會帶著整包歷史紀錄反覆空轉。
- **00:25 – 01:10（啟動小迴圈：修好自己停）**：輸入一鍵指令啟動 `python3 stop_loop_demo.py`。鏡頭特寫終端機輸出：
  - 第 1 步：外部測試立刻抓出 `factorial(0) == 1` 失敗（實測拿到 `0`）。
  - 第 2 步：針對邊界條件修正為 `if n <= 1: return 1`，3/3 測試全過。
  - **關鍵瞬間**：終端機印出 `🛑 [它自己停了！] 總共只跑 2 步就自動收手`，第 3 步備用動作完全不會被觸發。
- **01:10 – 01:45（死胡同保護：卡住自己停）**：展示當需求本身矛盾或連續 2 步沒有推進時，小迴圈不會硬拗到 100 步，而是在第 2 次零推進時立刻拉下煞車、印出卡關原因並停機。
- **01:45 – 02:00（結尾與信任感）**：回到 README 的一鍵指令與連結，收尾字幕：「真正好用的 AI，是你知道它什麼時候會自己停下來。」
